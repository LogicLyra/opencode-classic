### نقل إعداداتك من OpenCode

يستخدم OpenCode Classic Desktop ملفاً شخصياً منفصلاً لخادمه المدمج.
يعرض **الإعدادات > استيراد المحادثات** ومربع حوار أول تشغيل خياري
**المحادثات فقط** و**كل شيء (إعداد كامل)**. ينطبق سلوك الدمج التالي على
**المحادثات فقط**:
عند أول تشغيل، أو ضمن **الإعدادات > استيراد المحادثات**، اختر
**التحقق من قاعدة بيانات OpenCode الافتراضية** أو حدد ملف `.db`. أغلق
OpenCode أولاً، وراجع المصدر والوجهة والأعداد، ثم اختر **استيراد المحادثات
المؤهلة**.

- المصدر الافتراضي هو `$XDG_DATA_HOME/opencode/opencode.db`، وعادةً
  `~/.local/share/opencode/opencode.db`. اختر ملفاً للمسارات المخصصة أو
  قواعد بيانات قناة التطوير. الوجهة هي قاعدة بيانات خادم سطح المكتب
  المدمج النشط ضمن دليل `sidecar` في الملف الشخصي لسطح المكتب في Classic.
  لا تدعم أداة الاستيراد هذه الاتصالات البعيدة أو اتصالات الخادم الخلفي
  التجريبية.
- تدعم أداة الاستيراد الأولية مخططات SQLite وسجلات الترحيل المتطابقة.
  وهي لا ترحّل ملفات المصدر ولا تستورد تخزين JSON القديم. إذا فشلت
  فحوصات التوافق، فاستخدم إصدارات متوافقة من OpenCode وClassic وأعد
  المعاينة.
- تحتفظ المحادثات المحلية المكتملة بمعرفاتها وعناوينها وطوابعها
  الزمنية ورسائلها وأجزائها وسجلها v2 ومهامها ومسارات مشاريعها الأصلية.
  تُتخطى معرفات المحادثات الموجودة ككل؛ وإعادة الاستيراد لا تحدّث محادثة
  مستوردة سابقاً. المصدر للقراءة فقط، بما في ذلك سجل WAL الخاص به، ويُثبَّت
  كل استيراد ذرّياً.
- تُستثنى المحادثات التي تحتوي على مطالبات في قائمة الانتظار أو عملاً
  غير مكتمل أو تموضعاً صريحاً في مساحة عمل، وتُحتسب. الاستيراد لا يبدأ
  مطالبة ولا ينفذ أمراً أبداً. بيانات الاعتماد وحالة الحساب ومنح الأذونات
  وأوامر المشروع وملكية المشاركة والمرفقات الخارجية ولقطات Git ومسودات
  سطح المكتب لا تُنسخ. سجّل الدخول بشكل منفصل وأبقِ مجلدات مشروعك في
  مساراتها الأصلية. لقطات التراجع التاريخية غير متاحة؛ وتبقى بيانات
  المرفقات المضمنة في المحادثة، بينما يجب أن تظل الملفات الخارجية موجودة.
- افتح مجلد المشروع الأصلي في Classic لرؤية محادثاته المستوردة. هذه
  نسخة لمرة واحدة، وليست مزامنة مستمرة بين التطبيقين.

#### كل شيء (إعداد كامل)

أغلق OpenCode وأوقف أي عمليات كتابة أخرى أولاً. اختر **معاينة الإعداد
الافتراضي**، أو **اختيار مجلدات الإعداد** وحدد مجلدات OpenCode
لـ**البيانات** ثم **الإعدادات** ثم **الحالة**. توجد عادةً في
`~/.local/share/opencode` و`~/.config/opencode` و`~/.local/state/opencode`؛
ويُحترم تجاوز XDG. راجع الأعداد، وأقرّ بأنك تثق بالإعداد، وأكّد في مربع
الحوار الأصلي، ثم أعد تشغيل Classic لتنشيط الملف الشخصي المُجهَّز.

- يتطلب ملفاً شخصياً فارغاً لـ Classic المدمج على لينكس. لا تُستبدل
  المحادثات الموفرات والإعدادات المخصصة والحسابات والمشاريع المسجلة
  الموجودة أبداً. تُعرف ملفات الإعداد/الإضافات الافتراضية المُنشأة
  تلقائياً كحالة تمهيد.
- ينسخ جميع جداول قاعدة بيانات التطبيق البالغ عددها 19، و`auth.json`
  للموفرات، وحسابات السحابة، وبيانات اعتماد التكاملات، والأذونات، وبيانات
  المشاركة الوصفية، وملفات الإعداد (بما في ذلك JSONC)، والوكلاء
  والمهارات والإضافات والحالة والخطط ومخرجات الأدوات وملفات مساحات العمل
  واللقطات. تبقى المطالبات المعلقة في قائمة الانتظار؛ ولا ينفذها
  الاستيراد.
- تبقى مسارات المشاريع الخارجية دون تغيير على نفس الجهاز. يُعاد رسم
  المسارات الداخلية وأنماط الأذونات ومفاتيح اللقطات. تتلقى أشجار العمل
  المرتبطة بيانات Git الوصفية الخاصة، وتُجسَّد بدائل كائنات اللقطات حتى
  لا تعتمد النسخ على مخازن الكائنات الأصلية.
- يقرأ SQLite نسخة خاصة من قاعدة البيانات/WAL المصدرية. تُترك قاعدة
  البيانات المصدرية وWAL وملفات الذاكرة المشتركة دون تغيير. يستخدم
  التجهيز أذونات خاصة وسجل ملكية دائماً. يحدث التنشيط قبل بدء تشغيل
  الخادم المدمج ويستعيد عمليات إعادة تسمية الدلائل المقاطَعة. يُحتفظ
  بالملف الشخصي الأصلي الفارغ/التمهيدي تحت
  `.profile-import-retained-<operation-id>` في الملف الشخصي لسطح المكتب
  في Classic للفحص؛ ولا يُحذف تلقائياً.
- تبقى بيانات الاعتماد ملفات محلية محمية. يحافظ الإعداد الكامل أيضاً
  على السلوك القابل للتنفيذ: تحديث الحساب وتثبيت الاعتماديات والإضافات
  واتصالات MCP وأوامر المشروع وخطافات/أدوات Git المساعدة ومنح الأذونات
  يمكن أن تدخل حيز التنفيذ أثناء الاستخدام العادي بعد التنشيط. لا تستورد
  إلا إعداداً تثق به. قد يتطلب تدوير رموز OAuth تسجيل الدخول مرة أخرى
  عند استخدام كلا التطبيقين.
- تُعاد توليد السجلات وذاكرات التخزين المؤقت وأقفال العمليات. لا تُنسخ
  برامج النظام ومتغيرات بيئة الصدفة وتفضيلات نوافذ/شريط جانب لسطح
  المكتب الأصلي ومسودات سطح المكتب. ملفات المشاريع الخارجية مشتركة
  أصلاً في مساراتها الأصلية. افتح مجلد المشروع الأصلي للوصول إلى
  محادثاته.
- يتطلب سجل ترحيل ومخطط SQLite متطابقين. يقرأ الإعداد الكامل حالياً
  `opencode.db`؛ ويجب إزالة تجاوزات قاعدة البيانات/الإعداد/المصادقة
  الموفرة من البيئة قبل استخدامه. تُرفض مخازن JSON القديمة فقط،
  والمراجع الدائرية أو غير المدعومة لكائنات Git، وعقد الأجهزة،
  والملفات الشخصية التي تتجاوز 50 جيجابايت أو 500,000 عنصر جرد، مع
  سبب محدد. تُنسخ الروابط الرمزية الخارجية كما هي (تُجسَّد)؛ وتُتخطى
  الروابط المكسورة والمآخذ وملفات fifo وتُحتسب في الملخص. تُدعم ملفات
  الإعداد حتى 64 ميجابايت. يتطلب التجهيز مساحة قرص إضافية.
- أغلق OpenCode قبل الاستيراد. تحذّر المعاينة عند اكتشاف نسخة قيد
  التشغيل، وتُعاد محاولات نسخ اللقطات تلقائياً، ويُبلغ المصدر الذي
  يُكتب إليه باستمرار عن خط ازدحام مخصص يطلب منك إغلاقه.

لا يزال Classic المستقل عبر سطر الأوامر يستخدم جذور XDG الافتراضية لـ
OpenCode ما لم تتجاوزها. يحافظ أمر `uninstall` الخاص به على البيانات
وبيانات الاعتماد والإعداد وذاكرة التخزين المؤقت والحالة افتراضياً، بما
في ذلك مع `--force`. يتطلب حذف تلك الجذور المشتركة `--remove-shared-data`؛
ويتجاوز `--keep-data` و`--keep-config` ذلك الطلب لكل جذورهما. استخدم
`uninstall --dry-run` لمراجعة المسارات. قد يحذف مثبّت إلغاء تثبيت
المشروع الأصلي نفسه بيانات سطر الأوامر المشتركة. يرفض التفرع فتح قواعد
بيانات تحتوي ترحيلات غير معروفة؛ حدّث Classic بدلاً من تحرير سجل
الترحيل أو حذفه.

### التثبيت

```bash
curl -fsSL https://github.com/LogicLyra/opencode-classic/releases/latest/download/install | bash
```

> [!WARNING]
> حزمة npm‏ `opencode-ai` والحزم الحالية في Homebrew وScoop وChocolatey وAUR وNix توزع OpenCode الأصلي، وليس OpenCode Classic.

### تطبيق سطح المكتب (BETA)

تدعم إصدارات سطح المكتب من OpenCode Classic لينكس فقط وهي متاحة من [صفحة إصدارات التفرع](https://github.com/LogicLyra/opencode-classic/releases).

| المنصة    | التنزيل                                               |
| --------- | ----------------------------------------------------- |
| Linux x64 | ‏`opencode-classic-desktop-linux-*` (`.deb` أو `.rpm`) |

لا يُوزع AppImage عمداً. قد يجبر Ubuntu 24.04 والإصدارات الأحدث صور AppImage الخاصة بـ Electron على تعطيل عزل Chromium بموجب سياسة AppArmor الافتراضية؛ بينما تحافظ صيغا deb وRPM المثبتة على تكامل العزل الذي تتوقعه التوزيعة.

يمكن للمشرفين إعادة إنتاج بناء وحزم واختبار deb المثبت وبوابة الإصدار المرئية الكاملة باستخدام [دليل تشغيل QA للإصدار على جهاز لينكس الافتراضي](docs/linux-vm-qa.md).

#### دليل التثبيت

يحترم نص التثبيت ترتيب الأولويات التالي لمسار التثبيت:

1. `‎$OPENCODE_INSTALL_DIR‎` - دليل تثبيت مخصص
2. `‎$XDG_BIN_DIR‎` - مسار متوافق مع XDG Base Directory Specification
3. `‎$HOME/bin‎` - دليل الملفات التنفيذية القياسي للمستخدم (إن وُجد أو أمكن إنشاؤه)
4. `‎$HOME/.opencode/bin‎` - الخيار الاحتياطي الافتراضي

```bash
# أمثلة
OPENCODE_INSTALL_DIR=/usr/local/bin curl -fsSL https://github.com/LogicLyra/opencode-classic/releases/latest/download/install | bash
XDG_BIN_DIR=$HOME/.local/bin curl -fsSL https://github.com/LogicLyra/opencode-classic/releases/latest/download/install | bash
```
### Agents

يتضمن OpenCode وكيليْن (Agents) مدمجين يمكنك التبديل بينهما باستخدام زر `Tab`.

- **build** - الافتراضي، وكيل بصلاحيات كاملة لاعمال التطوير
- **plan** - وكيل للقراءة فقط للتحليل واستكشاف الكود
  - يرفض تعديل الملفات افتراضيا
  - يطلب الاذن قبل تشغيل اوامر bash
  - مثالي لاستكشاف قواعد كود غير مألوفة او لتخطيط التغييرات

بالاضافة الى ذلك يوجد وكيل فرعي **general** للبحث المعقد والمهام متعددة الخطوات.
يستخدم داخليا ويمكن استدعاؤه بكتابة `@general` في الرسائل.

تعرف على المزيد حول [agents](https://opencode.ai/docs/agents).
