### นำการตั้งค่าของคุณมาจาก OpenCode

OpenCode Classic Desktop ใช้โปรไฟล์แยกต่างหากสำหรับเซิร์ฟเวอร์ในตัว
**การตั้งค่า > นำเข้าแชท** และกล่องโต้ตอบการเปิดใช้งานครั้งแรกมีตัวเลือก
**เฉพาะแชท** และ **ทั้งหมด (การตั้งค่าเต็มรูปแบบ)** พฤติกรรมการผสาน
ต่อไปนี้ใช้กับ **เฉพาะแชท**:
เมื่อเปิดใช้งานครั้งแรก หรือภายใต้ **การตั้งค่า > นำเข้าแชท** ให้เลือก
**ตรวจสอบฐานข้อมูล OpenCode เริ่มต้น** หรือเลือกไฟล์ `.db` โปรดปิด
OpenCode ก่อน ตรวจทานแหล่งที่มา ปลายทาง และจำนวน แล้วจึงเลือก
**นำเข้าแชทที่มีคุณสมบัติ**

- แหล่งที่มาเริ่มต้นคือ `$XDG_DATA_HOME/opencode/opencode.db` ซึ่ง
  โดยปกติคือ `~/.local/share/opencode/opencode.db` เลือกไฟล์สำหรับ
  เส้นทางแบบกำหนดเองหรือฐานข้อมูลของช่องทางพัฒนา ปลายทางคือ
  ฐานข้อมูลของเซิร์ฟเวอร์เดสก์ท็อปในตัวที่ใช้งานอยู่ ภายใต้ไดเรกทอรี
  `sidecar` ของโปรไฟล์เดสก์ท็อปของ Classic ตัวนำเข้านี้ไม่รองรับ
  การเชื่อมต่อระยะไกลและเซิร์ฟเวอร์เบื้องหลังแบบทดลอง
- ตัวนำเข้าเริ่มต้นรองรับ schema ของ SQLite และประวัติการย้ายข้อมูล
  ที่ตรงกัน โดยไม่ย้ายข้อมูลไฟล์ต้นทางและไม่นำเข้าที่เก็บ JSON แบบ
  เดิม หากการตรวจสอบความเข้ากันได้ล้มเหลว ให้ใช้เวอร์ชัน OpenCode
  และ Classic ที่เข้ากันได้แล้วแสดงตัวอย่างอีกครั้ง
- แชทในเครื่องที่เสร็จสมบูรณ์ยังคงมี ID ชื่อ ตราเวลา ข้อความ
  ส่วนประกอบ ประวัติ v2 รายการสิ่งที่ต้องทำ และเส้นทางโครงการ
  เดิม ID ของแชทที่มีอยู่แล้วจะถูกข้ามทั้งหมด การนำเข้าซ้ำไม่ได้
  ปรับปรุงแชทที่นำเข้าไปแล้ว แหล่งที่มาเป็นแบบอ่านอย่างเดียว
  รวมถึงประวัติ WAL และการนำเข้าแต่ละครั้งคอมมิตแบบ atomic
- แชทที่มีพรอมต์รอคิว งานที่ยังไม่เสร็จ หรือการจัดวางพื้นที่ทำงาน
  แบบระบุชัดเจนจะถูกแยกออกและนับรวม การนำเข้าจะไม่เริ่มพรอมต์
  หรือรันคำสั่งเป็นอันขาด ข้อมูลรับรอง สถานะบัญชี สิทธิ์ที่อนุญาต
  คำสั่งโครงการ ความเป็นเจ้าของการแชร์ ไฟล์แนบภายนอก snapshot
  ของ Git และฉบับร่างของเดสก์ท็อปจะไม่ถูกคัดลอก โปรดลงชื่อเข้า
  ใช้แยกต่างหากและเก็บโฟลเดอร์โครงการไว้ที่เส้นทางเดิม snapshot
  การเลิกทำแบบย้อนหลังไม่สามารถใช้ได้ ข้อมูลไฟล์แนบแบบฝังยังคง
  อยู่ในบททึบ ส่วนไฟล์ภายนอกต้องยังคงมีอยู่
- เปิดโฟลเดอร์โครงการเดิมใน Classic เพื่อดูแชทที่นำเข้า นี่เป็น
  การคัดลอกครั้งเดียว ไม่ใช่การซิงก์อย่างต่อเนื่องระหว่างแอป

#### ทั้งหมด (การตั้งค่าเต็มรูปแบบ)

ปิด OpenCode และหยุดโปรเซสที่เขียนข้อมูลอื่น ๆ ก่อน เลือก
**แสดงตัวอย่างการตั้งค่าเริ่มต้น** หรือ **เลือกโฟลเดอร์การตั้งค่า**
แล้วเลือกโฟลเดอร์ **ข้อมูล** **การกำหนดค่า** และ **สถานะ** ของ
OpenCode โดยปกติอยู่ที่ `~/.local/share/opencode`
`~/.config/opencode` และ `~/.local/state/opencode` การ overrides ของ
XDG จะได้รับการปฏิบัติตาม ตรวจทานจำนวน รับทราบว่าคุณไว้วางใจ
การตั้งค่านี้ ยืนยันในกล่องโต้ตอบของระบบ แล้วรีสตาร์ท Classic
เพื่อเปิดใช้งานโปรไฟล์ที่จัดเตรียมไว้

- ต้องมีโปรไฟล์ Linux ในตัวของ Classic ที่ว่างเปล่า แชท ผู้ให้บริการ
  การตั้งค่าแบบกำหนดเอง บัญชี และโครงการที่ลงทะเบียนไว้ที่มีอยู่
  จะไม่ถูกเขียนทับเป็นอันขาด ไฟล์การกำหนดค่า/ปลั๊กอินเริ่มต้นที่
  สร้างขึ้นจะถูกจัดเป็นสถานะ bootstrap
- คัดลอกตารางฐานข้อมูลของแอปทั้ง 19 ตาราง `auth.json` ของผู้ให้
  บริการ บัญชีคลาวด์ ข้อมูลรับรองของการผสานรวม สิทธิ์ เมทาดาต้า
  ของการแชร์ ไฟล์การกำหนดค่า (รวมถึง JSONC) เอเจนต์ ทักษะ
  ปลั๊กอิน สถานะ แผน ผลลัพธ์เครื่องมือ ไฟล์พื้นที่ทำงาน และ
  snapshot พรอมต์ที่ค้างอยู่ยังคงอยู่ในคิว การนำเข้าจะไม่เรียก
  ใช้งานสิ่งเหล่านั้น
- เส้นทางโครงการภายนอกยังคงไม่เปลี่ยนแปลงบนเครื่องเดียวกัน
  เส้นทางภายใน รูปแบบสิทธิ์ และคีย์ snapshot จะถูกแมปใหม่
  worktree ที่เชื่อมโยงจะได้รับเมทาดาต้า Git ส่วนตัว และ alternates
  ของอ็อบเจกต์ snapshot จะถูก materialize เพื่อให้สำเนาไม่ขึ้นกับ
  ที่เก็บอ็อบเจกต์ต้นฉบับ
- SQLite อ่านสำเนาส่วนตัวของ DB/WAL ต้นทาง DB ต้นทาง WAL และ
  ไฟล์หน่วยความจำที่ใช้ร่วมกันจะไม่ถูกแตะต้อง การจัดเตรียมใช้
  สิทธิ์ส่วนตัวและบันทึกความเป็นเจ้าของแบบถาวร การเปิดใช้งาน
  เกิดขึ้นก่อนเซิร์ฟเวอร์ในตัวเริ่มทำงาน และกู้คืนการเปลี่ยนชื่อ
  ไดเรกทอรีที่ถูกขัดจังหวะ โปรไฟล์ว่าง/bootstrap ต้นฉบับจะถูกเก็บ
  ไว้ภายใต้ `.profile-import-retained-<operation-id>` ในโปรไฟล์
  เดสก์ท็อปของ Classic เพื่อตรวจสอบ และจะไม่ถูกลบโดยอัตโนมัติ
- ข้อมูลรับรองยังคงเป็นไฟล์ภายในที่ได้รับการป้องกัน การตั้งค่า
  เต็มรูปแบบยังคงรักษาพฤติกรรมที่ปฏิบัติการได้ การรีเฟรชบัญชี
  การติดตั้ง dependency ปลั๊กอิน การเชื่อมต่อ MCP คำสั่งโครงการ
  hook/ตัวช่วยของ Git และสิทธิ์ที่อนุญาต สามารถมีผลในการใช้งาน
  ปกติหลังการเปิดใช้งาน โปรดนำเข้าเฉพาะการตั้งค่าที่คุณไว้วางใจ
  การหมุนเวียนโทเคน OAuth อาจทำให้ต้องลงชื่อเข้าใช้อีกครั้งเมื่อ
  ใช้ทั้งสองแอป
- บันทึก แคช และการล็อกโปรเซสถูกสร้างขึ้นใหม่ โปรแกรมของระบบ
  ตัวแปรสภาพแวดล้อมของเชลล์ ค่ากำหนดหน้าต่าง/แถบข้างของเดสก์ท็อป
  อัปสตรีม และฉบับร่างของเดสก์ท็อปจะไม่ถูกคัดลอก ไฟล์โครงการ
  ภายนอกถูกใช้ร่วมกันอยู่แล้วที่เส้นทางเดิม เปิดโฟลเดอร์โครงการ
  เดิมเพื่อเข้าถึงแชทของมัน
- ต้องมีประวัติการย้ายข้อมูลและ schema ของ SQLite ที่ตรงกัน
  การตั้งค่าเต็มรูปแบบปัจจุบันอ่าน `opencode.db` การ overrides ของ
  ฐานข้อมูล/การกำหนดค่า/การยืนยันตัวตนที่สภาพแวดล้อมจัดหาให้ต้อง
  ถูกลบออกก่อนใช้งาน ที่เก็บแบบ JSON ล้วนแบบเดิม การอ้างอิง
  อ็อบเจกต์ Git แบบวนซ้ำหรือที่ไม่รองรับ device node และโปรไฟล์
  ที่เกิน 50 GiB หรือ 500,000 รายการคงคลัง จะถูกปฏิเสธพร้อมเหตุผล
  เฉพาะเจาะจง symlink ภายนอกถูกคัดลอกต่อเนื่อง (materialize)
  ลิงก์ที่ขาด socket และ fifo จะถูกข้ามและนับในสรุป รองรับไฟล์
  การกำหนดค่าสูงสุด 64 MB การจัดเตรียมต้องการพื้นที่ดิสก์เพิ่มเติม
- ปิด OpenCode ก่อนนำเข้า ตัวแสดงตัวอย่างจะเตือนเมื่อตรวจพบ
  อินสแตนซ์ที่กำลังทำงาน การคัดลอก snapshot จะลองใหม่โดยอัตโนมัติ
  และแหล่งที่มาที่ถูกเขียนต่อเนื่องจะรายงานข้อผิดพลาดแบบ busy
  เฉพาะเจาะจงขอให้คุณปิดมัน

CLI แบบสแตนด์อโลนของ Classic ยังคงใช้ราก XDG เริ่มต้นของ OpenCode
เว้นแต่คุณจะ override คำสั่ง `uninstall` ของมันจะรักษาข้อมูล
ข้อมูลรับรอง การกำหนดค่า แคช และสถานะไว้โดยค่าเริ่มต้น รวมถึง
กรณี `--force` การลบรากที่ใช้ร่วมกันเหล่านี้ต้องใช้
`--remove-shared-data` ส่วน `--keep-data` และ `--keep-config` จะ
override คำขอนั้นสำหรับรากที่เกี่ยวข้องของแต่ละตัว ใช้
`uninstall --dry-run` เพื่อตรวจทานเส้นทาง ตัวถอนการติดตั้งของ
อัปสตรีมเองอาจยังคงลบข้อมูล CLI ที่ใช้ร่วมกัน ฟอร์กนี้ปฏิเสธ
การเปิดฐานข้อมูลที่มี migration ที่ไม่รู้จัก โปรดอัปเดต Classic
แทนการแก้ไขหรือลบบันทึก migration

### การติดตั้ง

```bash
curl -fsSL https://github.com/LogicLyra/opencode-classic/releases/latest/download/install | bash
```

> [!WARNING]
> แพ็กเกจ npm `opencode-ai` และแพ็กเกจ Homebrew, Scoop, Chocolatey, AUR และ Nix ที่มีอยู่เผยแพร่ OpenCode อัปสตรีม ไม่ใช่ OpenCode Classic

### แอปเดสก์ท็อป (BETA)

บิลด์เดสก์ท็อปของ OpenCode Classic รองรับเฉพาะ Linux และพร้อมใช้งานจาก[หน้ารีลีสของฟอร์ก](https://github.com/LogicLyra/opencode-classic/releases)

| แพลตฟอร์ม | ดาวน์โหลด                                            |
| --------- | ----------------------------------------------------- |
| Linux x64 | `opencode-classic-desktop-linux-*` (`.deb` หรือ `.rpm`) |

AppImage ไม่ถูกเผยแพร่โดยเจตนา Ubuntu 24.04 และใหม่กว่าสามารถบังคับให้ AppImage ของ Electron ปิดใช้งาน sandbox ของ Chromium ภายใต้นโยบาย AppArmor เริ่มต้น รูปแบบ deb และ RPM ที่ติดตั้งแล้วจะรักษาการผสาน sandbox ที่ distribution คาดหวัง

ผู้ดูแลสามารถทำซ้ำการตรวจสอบรีลีสแบบครบถ้วน ทั้งบิลด์ การแพ็กเกจ การทดสอบ deb ที่ติดตั้งแล้ว และการตรวจสอบด้วยสายตา ด้วย[คู่มือ QA รีลีสบน VM Linux](docs/linux-vm-qa.md)

#### ไดเรกทอรีการติดตั้ง

สคริปต์ติดตั้งจะปฏิบัติตามลำดับความสำคัญต่อไปนี้สำหรับเส้นทางการติดตั้ง:

1. `$OPENCODE_INSTALL_DIR` - ไดเรกทอรีการติดตั้งแบบกำหนดเอง
2. `$XDG_BIN_DIR` - เส้นทางที่สอดคล้องกับ XDG Base Directory Specification
3. `$HOME/bin` - ไดเรกทอรีไบนารีมาตรฐานของผู้ใช้ (หากมีอยู่หรือสร้างได้)
4. `$HOME/.opencode/bin` - ค่าสำรองเริ่มต้น

```bash
# ตัวอย่าง
```

### เอเจนต์

OpenCode รวมเอเจนต์ในตัวสองตัวที่คุณสามารถสลับได้ด้วยปุ่ม `Tab`

- **build** - เอเจนต์เริ่มต้น มีสิทธิ์เข้าถึงแบบเต็มสำหรับงานพัฒนา
- **plan** - เอเจนต์อ่านอย่างเดียวสำหรับการวิเคราะห์และการสำรวจโค้ด
  - ปฏิเสธการแก้ไขไฟล์โดยค่าเริ่มต้น
  - ขอสิทธิ์ก่อนเรียกใช้คำสั่ง bash
  - เหมาะสำหรับสำรวจโค้ดเบสที่ไม่คุ้นเคยหรือวางแผนการเปลี่ยนแปลง

นอกจากนี้ยังมีเอเจนต์ย่อย **general** สำหรับการค้นหาที่ซับซ้อนและงานหลายขั้นตอน
ใช้ภายในและสามารถเรียกใช้ได้โดยใช้ `@general` ในข้อความ

เรียนรู้เพิ่มเติมเกี่ยวกับ [เอเจนต์](https://opencode.ai/docs/agents)

### เอกสารประกอบ

สำหรับข้อมูลเพิ่มเติมเกี่ยวกับวิธีกำหนดค่า OpenCode [**ไปที่เอกสารของเรา**](https://opencode.ai/docs)

### การมีส่วนร่วม

หากคุณสนใจที่จะมีส่วนร่วมใน OpenCode โปรดอ่าน [เอกสารการมีส่วนร่วม](./CONTRIBUTING.md) ก่อนส่ง Pull Request

### การสร้างบน OpenCode

หากคุณทำงานในโปรเจกต์ที่เกี่ยวข้องกับ OpenCode และใช้ "opencode" เป็นส่วนหนึ่งของชื่อ เช่น "opencode-dashboard" หรือ "opencode-mobile" โปรดเพิ่มหมายเหตุใน README ของคุณเพื่อชี้แจงว่าไม่ได้สร้างโดยทีม OpenCode และไม่ได้เกี่ยวข้องกับเราในทางใด
