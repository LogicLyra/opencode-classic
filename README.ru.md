### Перенос вашей настройки из OpenCode

OpenCode Classic Desktop использует отдельный профиль для встроенного сервера.
**Настройки > Импорт чатов** и диалог первого запуска предлагают **Только чаты**
и **Всё (полная настройка)**. Для **Только чаты** применяется следующее поведение
объединения:
При первом запуске или в разделе **Настройки > Импорт чатов** выберите
**Проверить базу данных OpenCode по умолчанию** или укажите файл `.db`. Сначала
закройте OpenCode, проверьте источник, назначение и счётчики, затем выберите
**Импортировать подходящие чаты**.

- Источник по умолчанию — `$XDG_DATA_HOME/opencode/opencode.db`, обычно
  `~/.local/share/opencode/opencode.db`. Укажите файл для нестандартных путей
  или баз данных канала разработки. Назначение — база данных активного
  встроенного сервера рабочего стола в каталоге `sidecar` профиля Classic.
  Этот импортёр не поддерживает удалённые и экспериментальные фоновые
  подключения к серверам.
- Импортёр поддерживает совпадающие схемы SQLite и истории миграций. Он не
  переносит файлы источника и не импортирует устаревшее JSON-хранилище. Если
  проверки совместимости не проходят, используйте совместимые версии OpenCode
  и Classic и повторите предпросмотр.
- Завершённые локальные чаты сохраняют свои ID, заголовки, метки времени,
  сообщения, части, историю v2, задачи и исходные пути проектов. Уже
  существующие ID чатов пропускаются целиком; повторный импорт не обновляет
  уже импортированный чат. Источник доступен только для чтения, включая его
  историю WAL, и каждый импорт фиксируется атомарно.
- Чаты с ожидающими промптами, незавершённой работой или явным размещением в
  рабочем пространстве исключаются и учитываются. Импорт никогда не запускает
  промпт и не выполняет команды. Учётные данные, состояние аккаунтов,
  разрешения, команды проекта, владение общими ресурсами, внешние вложения,
  снимки Git и черновики рабочего стола не копируются. Войдите отдельно и
  оставьте папки проектов по их исходным путям. Исторические снимки отмены
  недоступны; встроенные данные вложений остаются в переписке, а внешние файлы
  должны продолжать существовать.
- Откройте исходную папку проекта в Classic, чтобы увидеть импортированные
  чаты. Это разовая копия, а не постоянная синхронизация между приложениями.

#### Всё (полная настройка)

Сначала закройте OpenCode и остановите другие пишущие процессы. Выберите
**Предпросмотр настройки по умолчанию** или **Выбрать папки настройки** и укажите
папки OpenCode **данных**, **конфигурации** и **состояния**. Обычно они находятся
в `~/.local/share/opencode`, `~/.config/opencode` и `~/.local/state/opencode`;
переопределения XDG учитываются. Проверьте счётчики, подтвердите доверие
настройке, подтвердите в системном диалоге и перезапустите Classic для активации
подготовленного профиля.

- Требуется пустой встроенный Linux-профиль Classic. Существующие чаты,
  провайдеры, пользовательские настройки, аккаунты и зарегистрированные проекты
  никогда не перезаписываются. Созданные файлы конфигурации/плагинов по
  умолчанию распознаются как состояние начальной загрузки.
- Копируются все 19 таблиц базы данных приложения, `auth.json` провайдеров,
  облачные аккаунты, учётные данные интеграций, разрешения, метаданные общего
  доступа, файлы конфигурации (включая JSONC), агенты, skills, плагины,
  состояние, планы, вывод инструментов, файлы рабочих пространств и снимки.
  Ожидающие промпты остаются в очереди; импорт их не выполняет.
- Внешние пути проектов на той же машине не меняются. Внутренние пути, шаблоны
  разрешений и ключи снимков переназначаются. Связанные рабочие деревья
  получают приватные метаданные Git, а alternates объектов снимков
  материализуются, чтобы копии не зависели от исходных хранилищ объектов.
- SQLite читает приватную копию исходной БД/WAL. Исходная БД, WAL и файлы
  общей памяти остаются без изменений. Подготовка использует приватные права
  доступа и устойчивый журнал владения. Активация происходит до запуска
  встроенного сервера и восстанавливает прерванные переименования каталогов.
  Исходный пустой/начальный профиль сохраняется под
  `.profile-import-retained-<operation-id>` в профиле рабочего стола Classic
  для проверки; он не удаляется автоматически.
- Учётные данные остаются защищёнными локальными файлами. Полная настройка
  также сохраняет исполняемое поведение: обновление аккаунтов, установка
  зависимостей, плагины, MCP-подключения, команды проекта, а также
  хуки/вспомогательные программы Git и выданные разрешения могут вступать в
  силу при обычном использовании после активации. Импортируйте только ту
  настройку, которой доверяете. Ротация токенов OAuth может потребовать
  повторного входа при использовании обоих приложений.
- Журналы, кэши и блокировки процессов создаются заново. Системные программы,
  переменные окружения оболочки, upstream-настройки окон/боковой панели
  рабочего стола и черновики рабочего стола не копируются. Внешние файлы
  проектов уже общие по исходным путям. Откройте исходную папку проекта, чтобы
  получить доступ к её чатам.
- Требуются совпадающие история миграций и схема SQLite. Полная настройка
  сейчас читает `opencode.db`; предоставленные окружением переопределения
  базы данных/конфигурации/аутентификации нужно удалить перед использованием.
  Чистые устаревшие JSON-хранилища, циклические или неподдерживаемые ссылки на
  объекты Git, узлы устройств и профили свыше 50 ГиБ или 500 000 элементов
  инвентаря отклоняются с указанием конкретной причины. Внешние символические
  ссылки копируются целиком (материализуются); битые ссылки, сокеты и FIFO
  пропускаются и учитываются в сводке. Поддерживаются файлы конфигурации до
  64 МБ. Для подготовки требуется дополнительное место на диске.
- Закройте OpenCode перед импортом. Предпросмотр предупреждает при обнаружении
  запущенного экземпляра, копии снимков повторяются автоматически, а источник с
  непрерывной записью сообщает выделенную ошибку занятости с просьбой закрыть
  его.

Автономный CLI Classic по-прежнему использует корни XDG по умолчанию из OpenCode,
если вы их не переопределяете. Его команда `uninstall` по умолчанию сохраняет
данные, учётные данные, конфигурацию, кэш и состояние, в том числе с `--force`.
Для удаления этих общих корней требуется `--remove-shared-data`; `--keep-data` и
`--keep-config` переопределяют этот запрос для соответствующих корней. Проверьте
пути с помощью `uninstall --dry-run`. Собственный деинсталлятор апстрима всё же
может удалять общие данные CLI. Форк отказывается открывать базы данных с
неизвестными миграциями; обновите Classic вместо редактирования или удаления
журнала миграций.

### Установка

```bash
curl -fsSL https://github.com/LogicLyra/opencode-classic/releases/latest/download/install | bash
```

> [!WARNING]
> Пакет npm `opencode-ai` и существующие пакеты Homebrew, Scoop, Chocolatey, AUR и Nix распространяют апстрим-OpenCode, а не OpenCode Classic.

### Приложение для рабочего стола (BETA)

Сборки рабочего стола OpenCode Classic поддерживают только Linux и доступны на [странице релизов форка](https://github.com/LogicLyra/opencode-classic/releases).

| Платформа  | Скачать                                                |
| ---------- | ------------------------------------------------------ |
| Linux x64  | `opencode-classic-desktop-linux-*` (`.deb` или `.rpm`) |

AppImage намеренно не распространяется. Ubuntu 24.04 и новее может принудительно отключать песочницу Chromium у Electron AppImage при стандартной политике AppArmor; установленные форматы deb и RPM сохраняют ожидаемую дистрибутивом интеграцию песочницы.

Сопровождающие могут воспроизвести полную проверку сборки, упаковки, установленного deb и визуальную релизную проверку с помощью [рубука релизного QA на Linux-VM](docs/linux-vm-qa.md).

#### Каталог установки

Скрипт установки соблюдает следующий порядок приоритета для пути установки:

1. `$OPENCODE_INSTALL_DIR` - Пользовательский каталог установки
2. `$XDG_BIN_DIR` - Путь, соответствующий XDG Base Directory Specification
3. `$HOME/bin` - Стандартный пользовательский каталог бинарных файлов (если существует или может быть создан)
4. `$HOME/.opencode/bin` - Резервный вариант по умолчанию

```bash
# Примеры
OPENCODE_INSTALL_DIR=/usr/local/bin curl -fsSL https://github.com/LogicLyra/opencode-classic/releases/latest/download/install | bash
XDG_BIN_DIR=$HOME/.local/bin curl -fsSL https://github.com/LogicLyra/opencode-classic/releases/latest/download/install | bash
```
### Agents

В OpenCode есть два встроенных агента, между которыми можно переключаться клавишей `Tab`.

- **build** - По умолчанию, агент с полным доступом для разработки
- **plan** - Агент только для чтения для анализа и изучения кода
  - По умолчанию запрещает редактирование файлов
  - Запрашивает разрешение перед выполнением bash-команд
  - Идеален для изучения незнакомых кодовых баз или планирования изменений

Также включен сабагент **general** для сложных поисков и многошаговых задач.
Он используется внутренне и может быть вызван в сообщениях через `@general`.

Подробнее об [agents](https://opencode.ai/docs/agents).
