### Перенесіть свою конфігурацію з OpenCode

OpenCode Classic Desktop використовує окремий профіль для вбудованого
сервера. **Налаштування > Імпорт чатів** і діалог першого запуску
пропонують **Лише чати** та **Усе (повна конфігурація)**. Для **Лише чатів**
застосовується така поведінка об'єднання:
Під час першого запуску або в **Налаштування > Імпорт чатів** оберіть
**Перевірити типову базу даних OpenCode** чи вкажіть файл `.db`. Спочатку
закрийте OpenCode, перегляньте джерело, призначення та кількості, а потім
оберіть **Імпортувати придатні чати**.

- Типове джерело — `$XDG_DATA_HOME/opencode/opencode.db`, зазвичай
  `~/.local/share/opencode/opencode.db`. Для нетипових шляхів або баз даних
  каналу розробки вкажіть файл. Призначення — база даних активного
  вбудованого сервера робочого столу в каталозі `sidecar` профілю робочого
  столу Classic. Цей імпортер не підтримує віддалені та експериментальні
  фонові серверні з'єднання.
- Початковий імпортер підтримує відповідні схеми SQLite та історії
  міграцій. Він не мігрує файли джерела та не імпортує застаріле JSON-
  сховище. Якщо перевірки сумісності не проходять, використайте
  сумісні версії OpenCode і Classic та повторіть перегляд.
- Завершені локальні чати зберігають свої ідентифікатори, назви, мітки
  часу, повідомлення, частини, історію v2, завдання та початкові шляхи
  проєктів. Наявні ідентифікатори чатів пропускаються повністю; повторний
  імпорт не оновлює вже імпортований чат. Джерело доступне лише для
  читання, включно з історією WAL, і кожен імпорт фіксується атомарно.
- Чати з чергами запитів, незавершеною роботою або явним розміщенням у
  робочому просторі виключаються та обліковуються. Імпорт ніколи не
  розпочинає запит і не виконує команду. Облікові дані, стан акаунтів,
  надані дозволи, команди проєктів, власність спільного доступу, зовнішні
  вкладення, знімки Git і чернетки робочого столу не копіюються.
  Увійдіть окремо і тримайте теки проєктів у початкових шляхах.
  Історичні знімки скасування недоступні; вбудовані дані вкладень
  залишаються в транскрипції, а зовнішні файли мають далі існувати.
- Відкрийте початкову теку проєкту в Classic, щоб побачити імпортовані
  чати. Це одноразова копія, а не постійна синхронізація між
  застосунками.

#### Усе (повна конфігурація)

Спочатку закрийте OpenCode і зупиніть інші процеси запису. Оберіть
**Переглянути типову конфігурацію** або **Обрати теки конфігурації** та
вкажіть теки OpenCode: **дані**, **конфігурація**, потім **стан**. Вони
зазвичай містяться у `~/.local/share/opencode`, `~/.config/opencode` і
`~/.local/state/opencode`; перевизначення XDG враховуються. Перегляньте
кількості, підтвердьте, що довіряєте конфігурації, підтвердьте в
системному діалозі, потім перезапустіть Classic, щоб активувати
підготовлений профіль.

- Потребує порожнього вбудованого Linux-профілю Classic. Наявні чати,
  провайдери, користувацькі налаштування, акаунти та зареєстровані
  проєкти ніколи не перезаписуються. Згенеровані типові файли
  конфігурації/плагінів розпізнаються як стан початкового завантаження.
- Копіює всі 19 таблиць бази даних застосунку, `auth.json` провайдерів,
  хмарні акаунти, облікові дані інтеграцій, дозволи, метадані спільного
  доступу, файли конфігурації (включно з JSONC), агентів, навички,
  плагіни, стан, плани, вивід інструментів, файли робочих просторів і
  знімки. Запити в черзі залишаються в черзі; імпорт їх не виконує.
- Зовнішні шляхи проєктів залишаються незмінними на тій самій машині.
  Внутрішні шляхи, шаблони дозволів і ключі знімків перепризначаються.
  Пов'язані робочі дерева отримують приватні метадані Git, а
  альтернативи об'єктів знімків матеріалізуються, тож копії не залежать
  від початкових сховищ об'єктів.
- SQLite читає приватну копію джерельної бази/WAL. Джерельна база, WAL
  і файли спільної пам'яті залишаються незмінними. Підготовка
  використовує приватні дозволи та тривалий журнал власності. Активація
  відбувається до запуску вбудованого сервера і відновлює перервані
  перейменування каталогів. Початковий порожній/стартовий профіль
  зберігається під `.profile-import-retained-<operation-id>` у профілі
  робочого столу Classic для огляду; він не видаляється автоматично.
- Облікові дані залишаються захищеними локальними файлами. Повна
  конфігурація також зберігає виконувану поведінку: оновлення акаунта,
  встановлення залежностей, плагіни, з'єднання MCP, команди проєктів,
  хуки/допоміжні засоби Git і надані дозволи можуть діяти під час
  звичайного користування після активації. Імпортуйте лише ту
  конфігурацію, якій довіряєте. Ротація токенів OAuth може вимагати
  повторного входу при користуванні обома застосунками.
- Журнали, кеші та блокування процесів генеруються наново. Системні
  програми, змінні середовища оболонки, апстримні налаштування вікон/
  бічної панелі робочого столу та чернетки робочого столу не
  копіюються. Зовнішні файли проєктів уже спільні у початкових шляхах.
  Відкрийте початкову теку проєкту, щоб отримати доступ до її чатів.
- Потребує відповідної історії міграцій та схеми SQLite. Повна
  конфігурація зараз читає `opencode.db`; надані середовищем
  перевизначення бази/конфігурації/автентифікації слід вилучити перед
  використанням. Лише застарілі JSON-сховища, циклічні або
  непідтримувані посилання на об'єкти Git, вузли пристроїв та профілі
  понад 50 ГіБ або 500 000 позицій інвентарю відхиляються з конкретною
  причиною. Зовнішні символьні посилання копіюються повністю
  (матеріалізуються); розірвані посилання, сокети та fifo
  пропускаються та обліковуються у підсумку. Підтримуються файли
  конфігурації до 64 МБ. Для підготовки потрібен додатковий дисковий
  простір.
- Закрийте OpenCode перед імпортом. Перегляд попереджає при виявленні
  запущеного екземпляра, копії знімків повторюються автоматично, а
  джерело з безперервним записом повідомляє про виділену помилку
  зайнятості з проханням закрити його.

Окремий CLI Classic далі використовує типові корені XDG OpenCode, якщо ви
їх не перевизначаєте. Його команда `uninstall` типово зберігає дані,
облікові дані, конфігурацію, кеш і стан, зокрема з `--force`. Вилучення
цих спільних коренів потребує `--remove-shared-data`; `--keep-data` і
`--keep-config` перевизначають цей запит для відповідних коренів.
Перегляньте шляхи за допомогою `uninstall --dry-run`. Власний
деінсталатор апстриму все ж може видаляти спільні дані CLI. Форк
відмовляється відкривати бази даних з невідомими міграціями;
оновіть Classic замість редагування чи вилучення журналу міграцій.

### Встановлення

```bash
curl -fsSL https://github.com/LogicLyra/opencode-classic/releases/latest/download/install | bash
```

> [!WARNING]
> Пакет npm `opencode-ai` та наявні пакети Homebrew, Scoop, Chocolatey, AUR і Nix розповсюджують апстримний OpenCode, а не OpenCode Classic.

### Застосунок робочого столу (BETA)

Збірки робочого столу OpenCode Classic підтримують лише Linux і доступні зі [сторінки релізів форку](https://github.com/LogicLyra/opencode-classic/releases).

| Платформа | Завантаження                                          |
| --------- | ----------------------------------------------------- |
| Linux x64 | `opencode-classic-desktop-linux-*` (`.deb` чи `.rpm`) |

AppImage навмисно не розповсюджується. Ubuntu 24.04 і новіші можуть змушувати Electron AppImages вимикати пісочницю Chromium за типової політики AppArmor; встановлені формати deb і RPM зберігають інтеграцію пісочниці, очікувану дистрибутивом.

Супровідники можуть відтворити повну перевірку релізу — компонування, пакування, тест встановленого deb і візуальний контроль — за допомогою [документу QA релізів на Linux-ВМ](docs/linux-vm-qa.md).

#### Каталог встановлення

Скрипт встановлення дотримується такого порядку пріоритетів для шляху встановлення:

1. `$OPENCODE_INSTALL_DIR` - Власний каталог встановлення
2. `$XDG_BIN_DIR` - Шлях, сумісний із XDG Base Directory Specification
3. `$HOME/bin` - Стандартний каталог бінарних файлів користувача (якщо існує або може бути створений)
4. `$HOME/.opencode/bin` - Типовий резервний варіант

```bash
# Приклади
OPENCODE_INSTALL_DIR=/usr/local/bin curl -fsSL https://github.com/LogicLyra/opencode-classic/releases/latest/download/install | bash
XDG_BIN_DIR=$HOME/.local/bin curl -fsSL https://github.com/LogicLyra/opencode-classic/releases/latest/download/install | bash
```
### Агенти

OpenCode містить два вбудовані агенти, між якими можна перемикатися клавішею `Tab`.

- **build** - Агент за замовчуванням із повним доступом для завдань розробки
- **plan** - Агент лише для читання для аналізу та дослідження коду
  - За замовчуванням забороняє редагування файлів
  - Запитує дозвіл перед запуском bash-команд
  - Ідеально підходить для дослідження незнайомих кодових баз або планування змін

Також доступний допоміжний агент **general** для складного пошуку та багатокрокових завдань.
Він використовується всередині системи й може бути викликаний у повідомленнях через `@general`.

Дізнайтеся більше про [agents](https://opencode.ai/docs/agents).
